# bilibili-weekly-article

把期目录 docx 文字稿（必须用标题带「去注音」的版本）与图包素材排版成 B 站图文（Opus）：
上传配图、生成预览供人工审核，支持存草稿或直接发布并回读；署名（文案/文案审核）
从飞书「周报工作表」按期号拉取。

Agent 执行说明（工作流、脚本、API 细节）见 [SKILL.md](SKILL.md)。

## 在周报生产链路中的位置

周报从原始素材到全平台分发分两段，中间以「人工审核并手动发布」为界，本 skill 是第一段：

```text
期目录（docx「去注音」稿 + 图包素材 + 封面）
      │
      ▼
┌───────────────────────────────────────────┐
│ bilibili-weekly-article（B 站图文生产端）  │
│  解析素材 → 飞书拉取署名 → 上传配图        │
│  → 本地预览 → 提交 B 站草稿                │
└───────────────────────────────────────────┘
      │  草稿箱（article_id 回执）
      ▼
   ✋ 人工审核：核对版式、配图与署名，
      在 B 站编辑器手动点击「发布」
      │
      ▼
   已发布的 B 站周报图文（cv 号 / 公开链接）
      │
      ▼
┌───────────────────────────────────────────┐
│ weekly-cross-platform-sync（跨平台编排）   │
│  按期号 / cv 号定位已发布图文，            │
│  采集一次不可变素材清单后分发              │
└───────────────────────────────────────────┘
      ├──▶ xiaoheihe-weekly-sync ──▶ 小黑盒
      ├──▶ zhihu-weekly-sync     ──▶ 知乎
      └──▶ weibo-weekly-sync     ──▶ 微博
```

三条约定：

1. **B 站是首发平台**：本 skill 只把周报做成 B 站草稿，「发布」由人工在审核后手动完成，技能不代发；
2. **搬运的输入是已发布的图文**：各平台 skill 从 B 站公开页读取内容，必须等 B 站发布完成后才能启动 `weekly-cross-platform-sync`；以发布回执和公开页为准，不重新解析本地素材；
3. **两段可独立使用**：只有 docx 和素材时用本 skill；已有 B 站 cv 号时直接用对应搬运 skill，无需经过生产端。

## 安全试用与平台

Python 3.11+，支持 macOS 上的素材解析、本地预览及 B 站 API 流程。先在虚拟环境安装 `requirements.txt`，以 `--dry-run` 离线预演，再存线上草稿并人工审核。真实上传、存草稿和发布均须显式指定 `--account-id <目标UID>`；未完成标题/署名审核、存在警告或配图越界时停止。真实 build 和存草稿会上传图片，只有 dry-run 保证不访问网络。

不再支持 `--replace` 自动删除旧草稿。已有草稿/发布回执或未知提交时先人工核对，不通过删除回执盲目重发。完整步骤见 [SKILL.md](SKILL.md)。
